# Anchor0.31.1 framework /0.31.2 macro source audit

The observed current collector build pins anchor-lang and anchor-spl exactly to0.31.1, but its resolved nine macro crates and anchor-syn are0.31.2. Official archive comparison finds **65 of66 Rust files byte-identical across all ten0.31.1/0.31.2 macro/syn pairs**. The only changed Rust file is anchor-attribute-program/src/lib.rs: two example/doc URLs change their version tag and the feature-gated interface macro's deprecated-since string changes0.31.1→0.31.2. No functional implementation-body change was found in this exact pair comparison. That is useful negative source evidence; it is not compiled-output, macro-expansion, Cargo-identity or historical-graph equivalence.

## Exact source and manifest differences

The compared packages are anchor-attribute-access-control, account, constant, error, event, program; anchor-derive-accounts, serde, space; and anchor-syn. Each pair has identical file-path membership. Changed non-Rust files are .cargo_vcs_info.json, Cargo.toml, Cargo.toml.orig and embedded Cargo.lock. Normalized manifest differences are package version, package repository, and eight macro→anchor-syn dependency version bumps0.31.1→0.31.2. Anchor-derive-space declares no anchor-syn dependency; there are eight such edges, not nine. Feature definitions and all other normalized manifest fields agree after those explicit changes.

The sole Rust diff is retained at diffs/anchor-attribute-program/src/lib.rs.diff. The declare_program documentation link changes to the v0.31.2 example; the interface-instructions-gated deprecated attribute changes since and its example URL. Calling this implementation-identical without caveat would overstate it: deprecated metadata and documentation tokens do differ, and no actual macro expansion, Rust compilation or output comparison was performed. All66 source files and all changed Cargo/VCS/lock files remain available as authenticated data.

The error macro implementation is byte-identical in both versions. Its create_error emits file!()/line!(), owned name/message, numeric code, source origin and None compared values. Anchor-syn error and account-constraint generation source is likewise identical in this comparison. The retained owner generator still compares AsRef<AccountInfo>.owner with the specified owner address. Derive-serde/derive-accounts sources show no source-byte change. The separately retained anchor-lang0.31.1 require_gte macro returns error.with_values((value1,value2)) by value; with_values accepts two implToString values and formats them. Those framework sources were not compared with an unretained anchor-lang0.31.2 archive. Exact source identifiers/line numbers, including all three with_source methods, are recorded as descriptive witnesses. No macro execution or universal serialization/ownership equivalence follows.

## Why framework pins did not freeze the macros

The direct primary Cargo.toml pins =0.31.1 for anchor-lang and anchor-spl. The [official anchor-lang0.31.1 dependency metadata](https://crates.io/api/v1/crates/anchor-lang/0.31.1/dependencies) lists ^0.31.1 for its nine normal macro dependencies; its normalized archive manifest spells version0.31.1 without an equals sign. These ranges permit a0.31.2 choice. The observed current lock and source/dep-info analysis bind all nine macros plus anchor-syn0.31.2. It is a real version-resolution difference that the top-level exact framework pin alone did not prevent.

The current Cargo-unit record is authenticated by its retained9760c7 manifest and exact analysis bytes, with build-source37/source-plan/cache controls. Its counts distinguish252 locked registry packages from176 registry source roots observed in current dep-info. The present ten-pair comparison is not an audit of all176 roots or all252 lock entries. Cargo package identity, metadata hashes, transitive resolutions, embedded lockfile selections, code-generation-unit ordering and linker outcomes can still differ even when most procedural macro implementation text is equal. No version pin was changed or build trial launched.

## Temporal and historical limits

The secondary query across176 current registry package publication dates was not started by this task. It remains open. Root's separate mainnet-genesis/slot-to-time metadata query needs its own authenticated witness before connecting deployment dates to registry availability. This audit does not read or certify those remote results, and does not infer that a specific captured deployment used or could use0.31.2 merely from the dates retained here. Historical original crate graph, unit order, compiler flags/sysroot, real macro expansion and full original byte identity remain unproven.

The recovered source-origin differences also remain unexplained by this source-negative finding. Equal macro source still expands file!()/line!() in a particular input/module/workspace/remap context. Replacing a package version, forging source coordinates or padding bytes is not justified by these observations. No source, active status, manifest, lock, recipe, compiler option or selected artifact was modified.
