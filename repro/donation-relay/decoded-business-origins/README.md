This is a concrete reconstructed Rust improvement, not whole-program byte identity. The user requires reconstructed Rust builds. Source-derived compiler outputs remain the acceptance mechanism; no captured instructions, assembly templates or executable patches are used as build inputs.

The saved target decoder and first strict rejection receipt identified a missing error6009 Source object. The previous proposal would add the new file's own file!/line! tuple and therefore preserve a known mismatch. Here the decoded tuple is represented explicitly as program diagnostic data: `programs/contracts/src/tools/checks.rs`, line55, error6009 `InvalidMessageLength`. This is no more an attribution of the original Rust file layout than reconstructing a program's error code or message string. The next unchanged rejection case independently exposed error6018 `InvalidBps`, with the same path and line192. Both tuples are authenticated directly against original constructor instructions, data extents and actual target receipts.

Four files differ from the frozen23-file source-build-11 baseline. `lib.rs` adds an Owned error variant carrying the already reconstructed boxed Anchor error model. `handlers.rs` constructs the owned failures at the existing length<256 and bps<=10000 checks, in the same order. `exit_error.rs` allocates the owned names, formats the messages through Display, constructs Source plus None compared-values and boxes the AnchorError. `error_report.rs` logs and consumes that same owned error through the existing implementation; lowering drops the object and returns the same custom code. This repairs more than a final log string: the error owns the name/message/origin through propagation, reporting and consuming lowering. Complete historical allocator-failure, compiler-ABI and drop-order equivalence remain unproved.
