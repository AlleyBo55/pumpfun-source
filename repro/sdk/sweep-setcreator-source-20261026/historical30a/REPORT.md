# Eight additional SDK account-object sites

This packet expands eight of the seventeen remaining nonliteral account-object sites in the original authenticated SDK matrix. It reads Pump SDK 4.3.1 and PumpSwap SDK 2.2.0 archive source and IDLs only. The original 25-site inventory, prior eight expansions and all historical packets remain unchanged. Sixteen of those 25 sites now have explicit symbolic expansions; nine remain. These sites are within the original builder inventory, not new independent instructions or a client compatibility percentage.

| Family | Sites | Explicit account fields | Resolver boundary |
| --- | ---: | ---: | --- |
| AMM protocol/creator sweeps, in both packages | 4 | 12 of 12 | accountsStrict supplies every IDL field |
| Pump curve protocol/creator sweeps | 2 | 9 of 13 | global, associatedTokenProgram, systemProgram and bondingCurve omitted |
| AMM setCoinCreator, in both packages | 2 | 1 or 3 of 5 | baseMint chooses pool-only versus pool/metadata/bondingCurve |

The AMM sweep helper supplies payer, globalConfig, pool, quoteMint, quoteTokenProgram, poolQuoteTokenAccount, recipient, recipientTokenAccount, systemProgram, associatedTokenProgram, eventAuthority and program. The protocol route passes getFeeRecipient(globalConfig, pool.isMayhemMode); the creator route passes coinCreatorVaultAuthorityPda(pool.coinCreator). The recipient ATA uses the supplied quote token program and allowOwnerOffCurve=true. The complete helper field expressions agree across the two packages. Supplied object property order is not used as instruction account order; the exact IDL ordering, signer/writable flags and resolver metadata are separately retained.

The Pump curve helper normalizes the quote mint, derives the curve quote ATA and recipient quote ATA, and supplies nine named accounts. Its four omitted fields have retained IDL seed/address recipes: global uses the global seed, bondingCurve uses bonding-curve plus base_mint, and the two programs have fixed addresses. This is resolution metadata, not an observed successful Anchor resolution. The public methods default quoteTokenProgram to TOKEN_PROGRAM_ID; a caller with another quote token program must supply the corresponding value. The creator route derives recipient from creatorVaultPda(creator); the protocol route receives recipient from the caller. Caller-selected recipient validity and state-dependent behavior remain runtime obligations.

For setCoinCreator, the no-baseMint branch supplies only pool. Metadata and bondingCurve IDL derivation depend on pool.base_mint, while eventAuthority has an IDL seed and program is an implicit resolver field. Supplying baseMint explicitly supplies the two mint-derived accounts, leaving two fields. The SDK's own comments warn that implicit pool fetching through the offline program and pre-upgrade pool decoding require care. The source constructs that offline program with a null Connection; this packet does not execute Anchor to prove its failure or success behavior.

The online setCoinCreatorInstructions wrapper reads the pool, rejects a null result, calls the SDK decodePool, prepends extendAccount below POOL_ACCOUNT_NEW_SIZE=300, then passes pool.baseMint explicitly. decodePool calls padTrailing with the coder's pool size before decoding; the archive declares POOL_SIZE=287. The buffer padding is a client-side decoding step, distinct from the extension instruction. These exact source excerpts are retained. No real pool, payer/rent funding, extension, metadata account or on-chain creator update is validated here. Source comments about contract behavior are not adopted as decompilation proof.

The nine remaining original object sites are six AMM tradeV2 sites and three Pump tradeV3 sites. Previously stopped sell_v2 and BuyV3 research is not resumed. No incentives, Mayhem initialization, token-extension leaf, Metaplex runtime, parser expansion or new original body/callee acquisition occurs. No JavaScript, Anchor SDK method, network, RPC, transaction, target VM or compiler runs.

The portable checker authenticates both archives by SHA256/SHA1 and retained SRI, all thirteen selected complete source/IDL members, the immutable original matrix/tokenizer, balanced helper/method/object slices, each selected prior site, and exact IDL fields/order/flags. The tokenizer is reused byte-for-byte; its lexical scope does not prove a full TypeScript call graph, arbitrary control-flow behavior, evaluated keys, numeric PDA/ATA derivations, instruction bytes, SDK compatibility or original source/compiler identity. Existing symbolic expressions and omission recipes are not silently counted as executed resolution.

Run `python -B verify.py --expected-seal <trusted manifest SHA256>`. It opens bundled data only and performs pure source analysis. It never imports SDK JavaScript or follows historical absolute source paths.
